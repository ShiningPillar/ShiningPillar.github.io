## 介绍

> 翻译自 [官方手册](https://nim-lang.org/docs/manual.html#macros)

宏是一种**在编译期执行的特殊函数**，编译器把调用处的 AST（抽象语法树） 作为参数传给宏，宏在编译期运行、返回一个新的 AST，编译器再用它替换掉原来的宏调用。
我们可以用宏来添加自定义的语言特性，或者实现领域特定语言（DSL）

宏调用是一种特殊情况：语义分析并不完全按照自上而下、从左到右的顺序进行。相反，语义分析至少会进行两次：
1. 语义分析识别并解析该宏调用。
2. 编译器执行宏体（宏体可能会调用其他过程）。
3. 它用宏返回的 AST 替换宏调用的 AST。
4. 它对该代码区域重新进行语义分析。
5. 如果宏返回的 AST 中包含其他宏调用，则此过程会反复进行。
> 这就是为什么宏里写的代码"看起来没执行"——它只是被生成了，真正的语义检查/执行发生在替换之后。

虽然宏能够实现高级的编译期代码转换，但它们不能改变 Nim 的语法。
风格提示：为了代码的可读性，最好使用仍然具有表达力的最弱的编程构造。因此，“检查清单”是：
- 如果可能，使用普通 proc/iterator。
- 否则：如果可能，使用泛型 proc/iterator。
- 否则：如果可能，使用 template。
- 否则：使用 macro。
> 补充：template 是卫生的、语法级替换，比宏轻量；宏是AST 级变换，最重。能用 template 解决就别上宏。

关于执行方式：Nim 的宏在编译期由 VM（虚拟机） 解释执行，而不是编译成机器码运行。因此：
✅ 宏体里可以写几乎完整的 Nim 代码，做任意编译期计算
❌ 无法直接进行 C 层调用（不能 FFI、不能调用 C 函数、不能访问运行时指针）

文档：
[macro doc](https://nim-lang.org/docs/macros.html)



## 定义

### 基本签名

```nim
macro name(params): untyped =
  result = ...
```
- 返回类型通常是 untyped（宏返回 AST 节点）
- 宏体最后把结果赋给 result

### 多参数
可以向macro中传递多个块
```nim
macro debug(n: varargs[typed]): untyped =
macro performWithUndo(task, undo: untyped) = ...
```
### 多参数与缩进块
```nim
import macros

macro performWithUndo(task, undo: untyped): untyped =
  result = quote do:
    try:
      `task`
    finally:
      `undo`


expandMacros performWithUndo do:
  echo "开始做任务"
  echo "任务进行中"
do:
  echo "执行撤销/清理"

# 展开后类似于
try:
  echo "开始做任务"
  echo "任务进行中"
finally:
  echo "执行撤销/清理"
```
我们在`expandMacros performWithUndo do:...`处调用了两个宏：
使用performWithUndo对两个`do:`块进行ast替换；使用 expandMacros，查看宏展开：
1. 解析器先解析出一个完整语句：performWithUndo do: ... do: ...（因为 do 块被吸附）。
2. 这个语句整体成为 expandMacros 宏的 body 参数（untyped）。
3. expandMacros 宏体在编译期遍历 body，找到里面的 performWithUndo(...) 调用。
4. 它执行 performWithUndo（或请求编译器展开它），拿到展开后的 AST。
5. 把展开结果打印/回显，替换原处。


### 单语句 StmtList 的退化规则

```nim
expandMacros
  echo "a"
  echo "b"

expandMacros:
  echo "a"
  echo "b"
```
这两者的区别，前者 `expandMacros` 后面紧接的echo "a"是一个语句，但echo "b"是独立的下一个，所以不会包含
而 `expandMacros:` 则保证了两个echo都在一个语法块中
一个语法机制：`:` + `缩进` → `一个 StmtList`（语句列表/语句块）。

Nim 允许在任何调用/表达式后面用 : 引入块，这个块就作为一个参数。

普通 proc 不行（proc 参数要括号）
参数位置接受的是"表达式" 不是 语句块


单个子节点时，Nim 有一个规则：
只含一个语句的 StmtList 会退化为那个语句本身（不保留 StmtList 包装）。
所以 StmtList(BlockStmt) → 退化成 BlockStmt。

**真相：问题不在 block，在外层 StmtList 的退化条件**

# 通过add newCall 的方式，实现调试宏，打印变量名和变量值
macro myDebugEcho(args: varargs[untyped]): untyped =
  result = nnkStmtList.newTree()
  # iterate over any argument that is passed to this macro:
  for n in args:
    result.add newCall("write", newIdentNode("stdout"), newLit(n.repr))
    result.add newCall("write", newIdentNode("stdout"), newLit(": "))
    result.add newCall("writeLine", newIdentNode("stdout"), n)

macro anotherDebugEcho(arg: untyped): untyped = 
  result = quote do:

    echo astToStr(`arg`), ": ", `arg` # 这样是对的，得到的是 x: 42

expandMacros:
  myDebugEcho(x)
